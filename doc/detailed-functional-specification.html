01 / 范围与阅读约定

本文补充整体功能规格 v0.1，沿用单用户与授权 Agent、单块首版看板、六类基础卡片、锁定与可恢复删除的范围。本文中的字段、限额和工具名称是本项目的拟定契约，尚不表示已有实现或用户已逐项确认。

本文规定对外可见的数据和行为，供后续实现与验收使用；技术栈、存储方式、内部模块、通信传输选择与部署不在本次设计范围内。发生歧义时，本文中更具体的字段和行为约定用于细化整体规格。

三个不同层次：卡片定义描述控件规则；卡片状态保存用户与 Agent 共享的当前内容；页面草稿保存尚未提交的输入。草稿不会被 Agent 当作已确认数据读取。

  • 示例中的标识仅用于说明；标识视为不透明字符串，不根据前缀推断权限。
  • 下文 ? 表示输入可省略；除明确说明外，不接受 null；输出中可空字段固定输出为 null。
  • 所有 JSON 对象默认拒绝未声明字段；字符串长度按 Unicode 码点计算；时间为带时区的 RFC 3339 字符串，输出统一使用 UTC。
  • 表中的「只读」表示调用者不能写入。请求中包含只读字段应报错，不能静默忽略。

02 / 看板与公共类型

对象 / 字段类型与含义约束
Board.idstring，稳定看板标识。必有、只读；首版工具也必须明确传入目标看板。
name / description看板名称 / 用途说明。名称 1～80 字；说明最多 2,000 字；首版由用户设置。
revision非负安全整数，看板已提交卡片变更的全局顺序。初始为 0；每次有效卡片提交增加 1。资源读取、独立导入和修改看板名称不改变此值。
schema_versionstring，本项目数据契约版本。首版为 1.0；与 MCP 协议版本无关。
layout_policy布局规则。首版固定为 {columns:12, collision:"reject"}；含自动放置能力。
capabilities / limits支持类型、允许操作、文件及文本限额等。运行时可发现；下文给出的限额是首版建议默认值。
Actor{id:string, kind:"user"|"agent", display_name:string}由访问身份确定，调用者不得自行声明或冒充。
Permissions{read:boolean, create:boolean, edit:boolean, delete:boolean, restore:boolean, manage_lock:boolean, import_asset:boolean}服务返回调用者的有效权限；Agent 的 manage_lock 固定为 false。
Layout{x:integer,y:integer,w:integer,h:integer}基于 12 列网格；x≥0、y≥0、w≥2、h≥2、x+w≤12；w≤12、h≤24。高度单位为逻辑网格行，非像素。

看板 revision 只标识卡片集合及其版本，不能代表外部引用文件内容或看板管理设置。滑条、勾选框、输入框最小尺寸为 2×2；文本、图片、文件为 3×2；默认尺寸依次为文本 4×4、图片 4×4、文件 4×2、滑条 4×2、勾选框 3×2、输入框 4×2。

03 / 卡片公共结构

使用统一外壳与按类型区分的 props、state。首版固定类型、固定类型契约版本，不支持直接把文本卡片改成滑条。

字段类型 / 可写性具体规则
id / board_idstring / 只读稳定身份与所属看板，不能跨板改写。
type六类枚举 / 创建时写入text | image | file | slider | checkbox | input。
type_versionstring / 创建时写入首版统一 1.0，与类型一起校验。
titlestring / 可写必填，去除首尾空白后 1～120 字；不可把标题作为唯一身份。
descriptionstring / 可写用途或参数含义，最多 2,000 字，默认空字符串。
props类型专属对象 / 可写显示及输入定义；必须与 type、type_version 匹配。
state类型专属对象 / 可写当前正文、值或资源关联；不嵌入文件字节。
layoutLayout / 可写创建时可省略，由看板安排；输出必有实际位置与尺寸。
lockedboolean / 仅用户可管理默认 false。锁定保护卡片整体，Agent 不得通过 edit_card 写入。
lifecycleactive | deleted / 只读仅由删除与恢复操作改变。
version正安全整数 / 只读创建为 1；有效编辑、锁定、解锁、删除和恢复均增加 1。
last_revision正安全整数 / 只读该卡片最近一次有效变更的看板 revision。
created_at / updated_at时间字符串 / 只读创建时间不变；有效变更更新 updated_at。
created_by / updated_byActor / 只读由已验证的实际操作者生成。
deleted_at / deleted_by时间与 Actor，或 null / 只读active 时均为 null；删除时写入；恢复后清空，历史删除事件仍可在变化中辨认。

完整卡片示例

{
  "id": "card_kp", "board_id": "board_control",
  "type": "slider", "type_version": "1.0",
  "title": "比例增益 Kp", "description": "PID 控制器的比例增益",
  "props": {"min": 0, "max": 10, "step": 0.1, "unit": "", "precision": 1},
  "state": {"value": 2.5},
  "layout": {"x": 0, "y": 0, "w": 4, "h": 2},
  "locked": false, "lifecycle": "active", "version": 1, "last_revision": 1,
  "created_at": "2026-11-11T18:00:00Z", "updated_at": "2026-11-11T18:00:00Z",
  "created_by": {"id": "agent_1", "kind": "agent", "display_name": "工作 Agent"},
  "updated_by": {"id": "agent_1", "kind": "agent", "display_name": "工作 Agent"},
  "deleted_at": null, "deleted_by": null
}

列表摘要 CardSummary：包含 id、board_id、type、type_version、title、layout、locked、lifecycle、version、last_revision、updated_at、updated_by，并附 summary（最多 160 字）及 preview。摘要为服务生成的确定性摘录，不引入自动语义总结。preview 是以下按 type 区分的对象：

  • text：{text:string,truncated:boolean}，text 为正文前 160 字，truncated 表示还有正文。
  • slider：{value:number,unit:string}；checkbox：{checked:boolean,label:string}；input：{mode:"text"|"number",value:string|number|null,unit:string}，值不得截短，文本模式 unit 为空。
  • image／file：{asset_id:string,name:string|null}；name 无法取得时为 null。摘要读取不核对外部文件内容，资源实际状态以 get_asset_info 为准。

04 / 六类卡片的定义

下表列出 props 和 state 的全部首版字段。「默认」仅在创建或字段重置时应用；编辑未提供的字段保持原值。所有数值必须有限，禁止 NaN、Infinity 与数字字符串。

类型props 定义state 定义校验与行为
textformat:"plain"|"markdown"，默认 markdown。text:string，必填，可为空，最多 100,000 字。完整保留正文；只渲染基础 Markdown。内嵌 HTML 不执行，代码块按文本显示。
imagefit:"contain"|"cover"，默认 contain；alt:string 默认空，最多 500 字。asset_id:string 必填；caption:string 默认空，最多 2,000 字。创建和替换时必须引用可访问且可识别的图片；首版支持 PNG、JPEG、WebP、GIF。失效只影响预览，不清空说明。
filepreview:"auto"|"none"，默认 auto。asset_id:string 必填；note:string 默认空，最多 2,000 字。任意允许存储的文件类型；auto 不承诺都能预览；不执行文件。
slidermin:number,max:number,step:number 必填；unit:string 默认空，最多 24 字；precision:integer 默认 2，范围 0～6。value:number 必填。min<max、step>0；min、max、step、value 最多六位小数；value 位于闭区间，且等于 min+n×step，n 为非负整数。max 不是步长落点时，最高可选值为不超过 max 的最大落点；不得强行选中 max。
checkboxlabel:string 必填，1～200 字。checked:boolean 必填。不接受 null，不含「半选」状态；标题用于识别卡片，label 用于表达勾选含义。
inputmode:"text"|"number" 必填；placeholder:string 默认空，最多 200 字；required:boolean 默认 false；其他字段见下文。value:string|number|null 必填，具体类型由 mode 决定。创建后不能改变 mode；改用另一种输入时创建新卡片。可选输入的「未填写」统一保存 null。

输入框专属规则

  • 文本模式：仅再允许 max_length:integer，默认 500、范围 1～2,000。非空内容完整保留首尾空白；空字符串归一为 null。required=true 时，null、空串与仅空白内容无效。文本 "0" 是有效字符串。
  • 数值模式：仅再允许 min:number|null、max:number|null，默认 null；unit:string 默认空，最多 24 字；precision:integer 默认 2，范围 0～6。min≤max；值最多六位小数，满足已设置边界；required=true 时不允许 null。0 是有效数值。
  • precision：仅决定显示的最大小数位，不改变保存值。不足以准确显示当前值时，控件旁仍显示精确值；不得静默舍入实际状态。
  • required 由 false 改为 true，或调整边界后当前值不再有效时，必须在同一修改内给出有效的新值，否则整个修改失败。

最小创建内容示例

[
  {"type":"text","type_version":"1.0","title":"设计目标","props":{"format":"markdown"},"state":{"text":"最大超调量不超过 20%。"}},
  {"type":"image","type_version":"1.0","title":"阶跃响应","props":{"alt":"输出随时间变化的曲线"},"state":{"asset_id":"asset_plot","caption":"候选参数的仿真结果"}},
  {"type":"file","type_version":"1.0","title":"被控对象模型","props":{},"state":{"asset_id":"asset_model"}},
  {"type":"slider","type_version":"1.0","title":"Kp","props":{"min":0,"max":10,"step":0.1,"precision":1},"state":{"value":2.5}},
  {"type":"checkbox","type_version":"1.0","title":"验证状态","props":{"label":"已通过实验验证"},"state":{"checked":false}},
  {"type":"input","type_version":"1.0","title":"最大超调量","props":{"mode":"number","required":true,"min":0,"max":100,"unit":"%"},"state":{"value":20}}

05 / 资源模型与读取

字段含义与约束
id / board_id / mode稳定资源标识、所属看板、imported | reference。首版不允许跨看板直接引用资源。
name / mime_type / size_bytes名称 1～255 字；内容类型由服务检测；大小为非负整数，无法读取的引用可为 null。
source导入为 {kind:"upload"|"inline"|"approved_file"}；引用为 {root_id,relative_path}。不返回未授权系统绝对路径。
statusavailable | missing | forbidden | unreadable | too_large。读取或刷新时重新检查；这是查询结果，不是永远有效的保证。
resource_version / checked_at当前可读取内容的不透明版本标记与核对时间；不可取得内容时 version 可为 null。导入副本不可原地覆盖，替换须创建新资源。
created_at / created_by导入／建立引用的时间及身份，只读。
preview_kind / readable_as预览为 image、text 或 none；可读取格式为 text、bytes 的子集。首版只保证图片与 UTF-8 纯文本的直接预览，PDF、办公文档等可下载。

每个资源默认最多 20 MiB；inline 传入的原始字节最多 1 MiB，Base64 膨胀不计入原始限额；大文件通过用户文件选择或已授权目录导入。首版不提供任意远程 URL 抓取。引用目录列表只列出已获准位置，其授权与撤销由用户管理。

资源内容与卡片正文分开读取。图片返回实际可访问内容，无法内联到客户端时提供资源引用及字节读取方式。OCR、PDF 文本抽取、文件内容理解均不作为首版自动能力。

外部文件版本：引用文件可能在看板之外改变，因此读取每一片内容时须核对 resource_version。版本改变就中止本轮拼接，重新读取；不能把不同版本的分片拼成一份文件。锁定卡片也不会冻结被引用原文件，如需固定资料，应导入副本。

06 / 修改与版本语义

局部编辑方式

edit_card.changes 只允许 title、description、props、state、layout。标量替换；props、state、layout 中显式出现的直接子字段逐项替换；缺失字段保持原值。首版没有更深层次合并、数组拼接、删除字段或 JSON Patch。null 仅可用于类型明确允许为空的字段，不代表删除。

{
  "board_id":"board_control", "card_id":"card_kp",
  "expected_version":1, "command_id":"cmd_rename_001",
  "changes":{"title":"待验证的比例增益 Kp","props":{"max":12}}
}

此请求保留 min、step、value、其他元数据和布局；服务合并后整体校验，再一次提交。相同数值、相同正文或相同布局的无变化请求返回 changed:false，不增加 version 或 revision，也不更新最近修改者。

并发、幂等与权限判定

  1. 修改、删除、恢复以及用户锁定／解锁，都必须带 expected_version。首版按整张卡片检查，相同卡片的布局调整也会使旧编辑失效。
  2. 所有写工具（含资源导入）必须带 command_id（1～128 个 ASCII 可见字符，建议随机唯一值）。同一访问身份、同一看板内，command_id 跨写工具唯一。
  3. 相同 command_id、相同工具与完整输入的重试，返回第一次已确定的结果，附 replayed:true；请求内容不同则报 IDEMPOTENCY_KEY_REUSED。重试不得再次触发写入。
  4. 结果回执在首版不自动清除；确定的业务失败也保存回执。修正内容或解决冲突后是新意图，应使用新 command_id。处理中返回 OPERATION_PENDING，使用状态工具继续确认。
  5. 未授权身份不建立回执。每次读取回执仍需校验当前权限；不能因过去有权限而绕过已撤销的访问。
  6. 对新命令先检查访问权、对象存在性与生命周期、锁定、expected_version，再校验修改后内容和布局。全部有效才提交。已删除卡片不可 edit；删除／恢复的幂等例外见具体方法。

布局冲突

指定布局与活动卡片重叠时返回 LAYOUT_CONFLICT，不自动移动其他卡片。创建省略 layout 时，按从上到下、同一行从左到右寻找容纳默认尺寸的首个空位；恢复和用户「自动放置」使用相同规则。拖动、缩放只提交所操作卡片的新布局。

快照与变化衔接

首次快照返回固定 revision=R 的活动卡片集合和 snapshot_id；分页都读取这一状态，不能每页取不同时间点。收齐全部页面后才以 R 为起点读取变化。快照分页句柄有效 10 分钟，过期需从头取；列表分页亦固定读取时间点。

变化按 revision 升序返回，每个有效卡片变更一条记录，含 {revision,event_id,kind,card_id,card_version,actor,occurred_at,card_after}。kind 为 created、updated、locked、unlocked、deleted、restored；card_after 为该次提交后的完整卡片，包括删除状态，资源仍仅为引用。消费者以 after 中的 version 更新本地状态，忽略已应用的旧版本。

get_changes 首次确定截至 revision=T；分段读取到 T 后再请求下一轮。首版保证至少最近 30 天变化可用；since_revision 早于可用范围时返回 SNAPSHOT_REQUIRED 和最早可用标记。删除卡片及命令回执不因变化记录过期而被清除。

07 / MCP 契约与工具目录

以下 16 个名称是 AgentBoard 自定义的 MCP Tools，通过协议的工具发现与调用能力提供；它们本身不是 MCP 标准 RPC 方法。服务公布各工具的 inputSchema、outputSchema 与用途说明，使用结构化结果供 Agent 读取，业务执行失败通过工具结果中的 isError 表达。协议层未知方法、无效调用结构等错误与业务错误区分。参见MCP 官方 Tools 文档。

本文示例仅展示工具业务参数与 structuredContent，不是完整协议报文；握手、协议版本协商和协议要求的元数据由接入设计补充。首版不依赖通知唤醒 Agent，也不新增 Agent 执行循环。

分类首版工具用途
发现 / 3 个list_boards、get_board_info、get_card_types选择目标、了解权限和限制、查询类型契约。
读取 / 4 个get_card_list、read_card、get_board_snapshot、get_changes浏览、精读、恢复上下文和增量同步。
卡片写入 / 4 个push_card、edit_card、delete_card、restore_card卡片完整生命周期。
资源 / 4 个get_asset_sources、import_asset、get_asset_info、read_asset发现授权来源、添加资源、读取元信息与内容。
操作核对 / 1 个get_operation_status网络超时后核实结果、避免重复操作。

统一业务结果

{
  "ok":true,
  "data":{"card_id":"card_kp","version":2,"changed":true},
  "meta":{"request_id":"req_123","board_revision":2,"command_id":"cmd_rename_001","replayed":false}
}

成功为 {ok:true,data,meta}；失败为 {ok:false,error,meta}，互斥输出 data 与 error。meta 必有 request_id；与看板卡片状态有关时返回 board_revision；写工具回执带 command_id 和 replayed。board_revision 是本响应读取／提交的标记，不保证此刻仍是最新版本。

可分页输入公共字段：limit? 默认 20、范围 1～100；cursor? 首次省略。结果为 items、next_cursor（结束为 null）和对应快照标记。继续分页时保留首次筛选、排序和 limit 不变；cursor 不合法或与条件不匹配时拒绝。分页顺序固定，不静默跳项。

08 / 发现与读取方法

1. list_boards

输入
{limit?,cursor?}
输出
items 为 {id,name,description,revision,permissions}；按 id 升序；附 next_cursor。首版正常只返回一块获授权看板，无权限对象不列出。

2. get_board_info

输入
{board_id}
输出
Board、permissions、supported_types、limits、active_card_count、deleted_card_count；limits 含正文长度、资源大小、单页数量、快照有效期和变化保留期。无需另取卡片才知道限制。

3. get_card_types

输入
{board_id,type?}；省略 type 返回全部六类。
输出
{types:[{type,type_version,label,description,props_schema,state_schema,default_props,default_layout,min_layout}]}。props_schema 与 state_schema 为可机器校验的 JSON Schema，明确 required、枚举、允许 null、长度和边界；跨字段规则附 constraints 中文说明，例如 min 与 max、步长落点。JSON Schema 文档用服务声明的 dialect，不另造含义相近的字段。
异常
未知类型返回 UNSUPPORTED_TYPE；不提供未注册类型的创建建议。

4. get_card_list

输入
{board_id,lifecycle?:"active"|"deleted",type?,title_query?,limit?,cursor?}；默认 active。title_query 为标题的连续子串匹配，不区分拉丁字母大小写，最多 120 字。
输出
{items:CardSummary[],next_cursor,as_of_revision,list_id}。按 y、x、id 升序；过滤只影响列表，不改变读写权限。回收站使用 lifecycle=deleted。

5. read_card

输入
{board_id,card_id,include_deleted?:boolean}，默认 false。
输出
data 为 {card:Card}，正文完整，不返回摘要替代正文；资源仅返回 asset_id，可继续 get_asset_info / read_asset。
异常
已删除且未要求包含时返回 CARD_DELETED；资源失效不导致卡片自身读取失败。

6. get_board_snapshot

输入
{board_id,view?:"summary"|"full",limit?,cursor?}，默认 summary。
输出
{snapshot_id,revision,view,items,next_cursor,complete}。默认只含活动卡片，items 为 CardSummary 或 Card；complete 仅在本页为末页时为 true。full 含正文和控件值，不含资源字节。
读取策略
summary 适合会话初始浏览，可按 id 精读；若需要同一时点的完整集合必须选 full，不能把随后 read_card 得到的新版本当作旧快照内容。

7. get_changes

输入
{board_id,since_revision,limit?,cursor?}；since_revision 为已完整消费的非负整数。
输出
{from_revision,to_revision,items:Change[],next_cursor,next_since_revision,complete}。next_since_revision 为本页最后一条已返回 revision，无条目时等于 from_revision；complete=true 时等于 to_revision。使用 cursor 消费本批后再用 next_since_revision 开新批。
异常
未来 revision 返回 INVALID_ARGUMENT；过旧返回 SNAPSHOT_REQUIRED。每页按完整事件切分，单个正文较大不截断事件。

09 / 卡片写入方法

所有方法均按第 06 节处理 command_id。返回卡片内容是该操作提交时的结果，重放回执时可能已经过时；需要现值应重新 read_card。

8. push_card

输入
{board_id,command_id,card:{type,type_version,title,description?,props,state,layout?}}。props 可为 {}，但必填定义仍需提供；state 不省略。
输出
{card:Card,changed:true,placement:"requested"|"automatic"}。系统补齐默认值、身份、标识、版本和位置。Agent 不能创建时附加 locked=true。
失败
未知类型、无效初始值、资源不存在／不可用、指定布局冲突；失败不留下半张卡片。

9. edit_card

输入
{board_id,card_id,expected_version,command_id,changes}；changes 至少有一个可编辑字段，遵守局部合并规则。
输出
{card:Card,changed:boolean}。验证合并后的完整卡片；不支持更改 type、mode、身份、锁定或生命周期。
失败
CARD_LOCKED、VERSION_CONFLICT、VALIDATION_FAILED、LAYOUT_CONFLICT。两侧编辑都不能绕过锁定。

10. delete_card

输入
{board_id,card_id,expected_version,command_id}
输出
{card:Card,changed:boolean}。首次删除版本递增并记录删除者。已删除且 expected_version 匹配当前版本时返回 changed=false；版本不匹配仍冲突。
效果
卡片从正常视图移除，保留内容和资源引用。锁定卡片须先由用户解锁；不删除资源或磁盘原文件。

11. restore_card

输入
{board_id,card_id,expected_version,command_id}
输出
{card:Card,changed:boolean,layout_adjusted:boolean}。删除卡片恢复时沿用原 id；原位置可用则保留，否则自动安排。已 active 且版本匹配时返回 changed=false。
资源失效
允许恢复卡片与说明，不要求引用原文件重新可用；前端显示资源实际状态。

锁定方法归属：首版 MCP 不暴露锁定／解锁工具。用户前端管理操作采用相同 expected_version、command_id 语义。锁定与解锁各形成一次卡片变更。用户权限变更、授权目录管理同样仅放在前端管理入口。

10 / 资源与操作状态方法

12. get_asset_sources

输入
{board_id}
输出
{roots:[{root_id,label,can_import,can_reference}],inline_max_bytes,asset_max_bytes}；仅返回已获准来源和逻辑标签，不枚举全部文件。

13. import_asset

输入
{board_id,command_id,name,mode,source}。mode 为 imported 或 reference；source 是以下二选一。
  • {kind:"inline",mime_type,data_base64}：仅允许 mode=imported；解码后最多 1 MiB，类型声明须与检测结果兼容。
  • {kind:"approved_file",root_id,relative_path}：可导入副本或引用；relative_path 必须位于已批准根目录中，不允许绝对路径、越界或通过链接访问范围外目标。
输出
{asset:Asset}，不自动创建卡片。mode=imported 固定保存当前副本；mode=reference 保留受控引用。请求重试返回同一 asset_id。
补充
用户文件选择／拖入采用同一资源模型，服务接受成功后再创建卡片；未被卡片引用的已导入资源首版不自动清理，可在资源选择面板重新使用。用户撤销目录授权后，依赖该目录的引用变为 forbidden。

14. get_asset_info

输入
{board_id,asset_id}
输出
{asset:Asset}，核对当前来源并返回 checked_at、resource_version 与 status；可辨认的已存在资源发生失效时，以 status 表达，不伪造为不存在。

15. read_asset

输入
{board_id,asset_id,format:"text"|"bytes",resource_version?,cursor?}。首次无 cursor；若要读取此前元信息所指内容，传 resource_version。
输出
{asset_id,resource_version,format,offset,content,next_cursor,complete}。text 仅支持 UTF-8 纯文本，content 为最多 32,768 码点的完整字符片段，offset 单位为码点；bytes 的 content 为原始字节最多 256 KiB 的 Base64，offset 单位为字节。分片连续、不重叠；结束时 next_cursor=null。空文件也返回一次 complete=true 的空片段。
一致性
后续 cursor 绑定资源、身份、格式和 resource_version，有效 10 分钟；不可改变条件。引用内容变化返回 ASSET_CHANGED，提示重新开始；失效返回具体资源错误。
图片兼容
支持的客户端可额外获得 MCP 图片内容块或资源链接；结构化字节读取始终可用。资源 URI 的方案与协议承载另行确定，不能让链接成为绕过授权的入口。参见MCP 官方 Resources 文档。

16. get_operation_status

输入
{board_id,command_id}；只查询当前身份发起的命令。
输出
{status:"unknown"|"pending"|"succeeded"|"failed",result}。前两种 result=null；后两种为原业务结果封装。unknown 只表示未查到已登记操作，不能断言某个在途请求不会随后到达。
后续行动
pending 时稍后查询；unknown 时可用同一 command_id 和相同输入重试；succeeded／failed 依据原结果处理。不要换新命令来猜测重试。

11 / 错误与响应示例

error 结构为 {code,message,field_errors,retryable,recovery,details}。field_errors 为 [{path,code,message}]，无字段错误时为空数组；details 只返回当前权限允许的信息；message 与 recovery 为中文。

错误码发生条件处理动作 / retryable
INVALID_ARGUMENT / VALIDATION_FAILED输入结构错误、越界、无效定义或合并后不合法。改正参数后用新 command_id / false。
UNAUTHORIZED / FORBIDDEN身份无效或没有操作权限。恢复身份或由用户调整权限 / false。
NOT_FOUND目标不存在或不可向调用者披露其存在。核对目标；不回传私有内容 / false。
CARD_DELETED / CARD_LOCKED编辑已删除卡片或修改锁定卡片。恢复卡片或请求用户解锁，再重新读取 / false。
VERSION_CONFLICTexpected_version 与当前版本不同。返回可访问的 current_version，重新读取后重建修改 / false。
LAYOUT_CONFLICT指定网格与活动卡片重叠。调整位置或使用自动放置 / false。
UNSUPPORTED_TYPE未支持的 type、type_version 或读取格式。查询支持能力 / false。
ASSET_UNAVAILABLE / ASSET_CHANGED缺失、无权访问、不可读或读取中内容改变。details.reason 对应资源状态；修复来源或重开读取 / false。
LIMIT_EXCEEDED正文、文件或请求超过公布限制。减少内容或选择支持的导入方式 / false。
CURSOR_INVALID / CURSOR_EXPIRED条件不匹配、标记无效或已过期。重新从首段读取，快照需重新开始 / false。
SNAPSHOT_REQUIRED增量起点已不在保留范围内。获取完整快照 / false。
IDEMPOTENCY_KEY_REUSED同一命令标识被用于不同请求。核对意图，新操作使用新标识 / false。
OPERATION_PENDING / SERVICE_UNAVAILABLE原命令处理中或暂时不可用。查状态或使用同一命令重试 / true。

retryable=true 仅表示允许在条件未改变时重试，不能保证下一次成功；返回业务结果未知的网络中断不等于一次失败回执。协议级拒绝的参数结构错误可能没有业务回执。

冲突结果示例（structuredContent）

{
  "ok":false,
  "error":{
    "code":"VERSION_CONFLICT",
    "message":"卡片已被其他操作者更新，本次修改未保存。",
    "field_errors":[], "retryable":false,
    "recovery":"重新读取卡片，确认最新内容后使用新命令提交。",
    "details":{"card_id":"card_kp","expected_version":1,"current_version":2}
  },
  "meta":{"request_id":"req_124","board_revision":2,"command_id":"cmd_old_001","replayed":false}
}

此类工具执行失败的 MCP 结果标记 isError=true；结构化内容与给人阅读的说明表达同一结果，不应出现一处成功、一处失败。

区域展示内容操作行为
顶部工作区栏名称、标识、连接状态、总体保存状态。复制看板标识；打开设置。总体状态有「未保存、保存中、已保存、保存失败、存在冲突、离线」。优先展示需要用户处理的状态。
工具栏添加、资源导入、搜索、回收站。添加弹出六类卡片选择；搜索支持标题和完整标识。只在活动卡片内筛选，回收站单独搜索；首版不提供正文全文搜索。
卡片画布12 列网格、标题、内容、拖动把手、菜单、最近保存状态。点击卡片选中，打开属性；仅拖动把手或缩放边角调整布局；点击控件只改变其值，不移动卡片。
属性面板标题、描述、类型定义、完整内容、布局、标识与修改信息。内容／定义／布局分组；只编辑可写字段；显示校验错误；保存和取消。只读信息不放成可编辑输入。
资源选择对话框已添加资源、导入副本、受控引用；名称、模式、可用状态。用户选择本地文件上传；引用时选择授权目录与相对位置；完成后在原卡片编辑中填入 asset_id。
图片／文件查看层大图、说明、资源来源和最近核对时间。图片缩放；文本预览；获取原文件；引用资源提供「刷新资源」。替换资源进入编辑流程。
回收站已删除列表、标题、类型、删除时间和删除者。读取完整内容、恢复；没有永久删除按钮。恢复后定位卡片并说明位置是否变化。
最近变更面板最近 50 条变更，包含操作者、动作、卡片标题与时间。定位仍存在的卡片；已删除项跳转回收站。无逐字段历史差异与回滚入口。
设置看板名称、说明、Agent 访问范围、已授权资源目录。用户管理授权；撤销目录时说明哪些引用受影响。首版无创建多看板入口。

卡片菜单与锁定

活动卡片菜单包含编辑、复制标识、定位、锁定／解锁、删除。锁定后禁用内容编辑、控件、拖动、缩放与删除，并显示锁图标和中文状态；读取与复制标识可用。用户显式解锁后才恢复编辑。不设置仅凭创建者身份决定的隐藏权限。

小窗口与键盘

窄屏时卡片按 y、x、id 顺序单列展示；桌面网格布局不被改写，窄屏关闭直接拖拽和缩放，仍可通过属性中的坐标与尺寸编辑布局。属性面板改为全屏编辑层。键盘可选中卡片、输入、操作控件，并通过布局表单替代拖动；焦点与错误说明可辨认。

13 / 页面交互与保存

操作草稿与提交时机成功／失败反馈
添加卡片对话框中填写，点「创建」才提交；默认位置自动安排。成功后选中并定位新卡片；失败保留输入；创建请求未确认前不重复发送新命令。
编辑标题、正文、定义面板内暂存草稿，点「保存修改」一次提交本次实际改动。取消放弃草稿。成功显示实际版本；失败在字段旁说明。离开有草稿的面板时提供继续编辑／放弃／保存选项。
滑条拖动过程只预览；松开一次提交。键盘调整在 300 毫秒无新按键或失焦时提交一次；精确数值输入以 Enter 或失焦提交。显示保存中；失败保留待重试值，旁边展示最后已保存值。待确认期间同控件禁用重复提交，不影响其他卡片。
勾选框切换一次提交，pending 时禁用该控件。失败显示原已保存状态与此次待保存意图，可重新读取后重试。
卡片内输入框输入为草稿；Enter 或失焦时提交；Escape 恢复最后已保存值。本地无效输入不提交；服务拒绝时保留原输入并标注错误，Agent 仍读到旧已保存值。
拖动／缩放松开后提交新布局；过程中显示网格吸附与冲突提示。成功使用实际位置；失败恢复已保存位置并提示，不自动推开其他卡片。
删除确认目标后提交，说明可在回收站恢复。成功移除；可显示恢复入口；失败保留卡片。
导入与替换资源先成功添加资源，再创建或编辑卡片。替换前保持旧资源关联。第二步失败不会清空旧卡片；已添加资源可稍后重用。

同一卡片的编辑互斥

本页面对同一卡片只保留一个活动草稿编辑入口：属性面板有未保存改动时，卡片内联控件、拖动和缩放暂时禁用；切换到另一编辑入口前先处理草稿。同一卡片已有请求进行中时，不并行发起第二个写请求。其他客户端或 Agent 的并发仍按版本冲突处理。

外部更新与冲突处理

  1. 卡片没有本地草稿时，应用新版本并短暂提示修改来源，不强制滚动到该卡片。
  2. 有本地草稿时，保留草稿，不自动混入新正文；显示「已有新版本」。
  3. 冲突层展示最新已保存内容和本地待保存改动；可选「采用最新版本」或「保留草稿，基于最新版本重新编辑」。后者须重新审阅本地改动，使用最新 version 与新 command_id 提交，不提供静默强制覆盖。
  4. 若新状态为删除或锁定，保留可复制的本地草稿；暂停提交，分别引导恢复或解锁。

断线、未确认结果与空状态

离线时可以继续在当前页面保留已打开的草稿，但禁用写入和资源刷新。连接恢复后先核对未确认命令，再读取变化或新快照，之后处理草稿冲突；不自动把离线草稿当作新值覆盖。页面关闭不保证恢复未保存草稿，离开前提示。

空看板展示「添加第一张卡片」和「让 Agent 向当前看板推送卡片」说明；搜索无结果提供清除筛选；无可用目录提供由用户配置来源的入口；资源预览失败保留卡片标题、说明与重试／替换操作。

14 / 完整调用示例

以下按顺序发生，假设看板初始 revision=0，自动分配标识 card_kp。省略完整输出中的审计字段，但请求片段均是业务参数，不是 JSON-RPC 报文。

① 确认工作区与类型

{"tool":"get_board_info","arguments":{"board_id":"board_control"}}
{"tool":"get_card_types","arguments":{"board_id":"board_control","type":"slider"}}

② 创建 Kp 卡片

{
  "tool":"push_card",
  "arguments":{
    "board_id":"board_control","command_id":"cmd_create_kp",
    "card":{"type":"slider","type_version":"1.0","title":"比例增益 Kp",
      "props":{"min":0,"max":10,"step":0.1,"precision":1},"state":{"value":2.5}}
  }
}

成功：id=card_kp、version=1、last_revision=1。用户在网页将 Kp 保存为 3.0 后，version=2、revision=2。

③ Agent 读取变化，获取精确新值

{"tool":"get_changes","arguments":{"board_id":"board_control","since_revision":1}}

变化中的 card_after.state.value=3.0；操作者为 user。若 Agent 持有的快照过旧，就先取新快照，不依赖聊天中曾经出现的 2.5。

④ 基于最新版本只修改说明

{
  "tool":"edit_card",
  "arguments":{"board_id":"board_control","card_id":"card_kp",
    "expected_version":2,"command_id":"cmd_explain_kp",
    "changes":{"description":"当前候选值，尚待实验验证。"}}
}

成功后 version=3、revision=3，state.value 仍为 3.0。若此时发生超时，使用 get_operation_status 查询 cmd_explain_kp；不要改用新命令重复发起。

⑤ 分开处理业务结果与验证事实

Agent 可以添加分析文字和仿真图片；若没有实验依据，不应把「已通过实验验证」勾选为 true。框架负责保留操作者与状态，不替 Agent 判断结论是否正确。

15 / 验收与边界

整体规格 AT-01～15 继续适用，增加以下可验证断言。

编号验证点预期结果
DT-01六类创建输入、返回默认值和 read_card 结果。均符合类型定义；只读字段不可写；类型与 input.mode 不可改。
DT-02滑条浮点步长、边界不落点、输入 null／0／空串。按公开规则校验，精确值不因显示精度改变。
DT-03只改 props.max，同时检查 min、step、state。未指定字段保留；导致当前值失效则整个修改失败。
DT-04重复命令、换参数复用命令、结果未知后查询。重放原结果、不重复写入；不同参数拒绝；状态不把 unknown 误作确定失败。
DT-05无变化修改、重复删除／恢复、锁定与解锁。无变化不升版本；有效生命周期和锁定变更同时升卡片 version 与看板 revision。
DT-06快照分页期间用户继续更新卡片。快照各页属于同一个 revision；消费后接增量可获得后续修改，无遗漏。
DT-07增量分段、过期 cursor、超过变化保留期。顺序与续读标记明确；过期重读；记录不足返回 SNAPSHOT_REQUIRED。
DT-08读取大文本与多片文件，引用中途改变。内容不静默截断；外部版本改变报错，不混合拼接。
DT-09授权撤销后读取资源、恢复带失效引用的卡片。访问拒绝；卡片与说明可恢复；旧权限与锁定不构成文件冻结。
DT-10拖动控件、拖动把手、指定重叠布局、自动放置。控件操作不移动卡片；布局冲突不移动旁人卡片；自动位置确定可见。
DT-11属性面板草稿与内联编辑、外部更新、断线恢复。同页同卡只一个入口；草稿可保留；没有静默覆盖。
DT-12窄屏阅读、键盘输入与布局编辑。主要操作可达，单列展示不改变共享网格坐标。

16 / 依据与后续设计

需求来源为「开源设计实例调研」对话和本项目整体功能规格。本次新增的字段、限额、分页寿命、回执保留规则、页面区域及保存时机均为设计建议，供后续评审与实现依据使用。

协议事实参考 MCP 官方 Tools 文档与Resources 文档（核对日期：2026-11-11）。本项目自定义工具的名称、参数、分页与错误码由本文定义，不声称来自协议标准。

后续技术设计需要另行确定接入与鉴权、协议承载、资源传输、页面状态同步、持久保存及备份策略。多看板、按钮事件、图表表格、批量编辑、完整历史回滚和主动调度仍属于整体规格的 P1 范围，不混入首版接口。
