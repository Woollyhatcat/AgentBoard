01定位与目标

AgentBoard 是面向用户与 Agent 协作的通用共享黑板框架。产品提供网页看板与配套服务，并向 Agent 提供 MCP 操作能力。看板上的一切元素统称为「卡片」，可以承载文字、图片、文件以及交互控件。

信息持续存在

重要约束、待办、资料和阶段结论可跨页面关闭、服务正常重启及对话切换保留。

双方共同维护

用户和 Agent 操作同一份卡片状态，创建者身份不自动决定卡片归属或编辑权。

用控件表达意图

用户调整参数、勾选选项或补充文本，Agent 在后续读取中获得最新信息。

关键边界：看板保存共享信息，Agent 在工作时读取并使用这些信息。网页变化不会自动启动 Agent 推理；看板也不保证 Agent 永久记住已经读取过的内容。

成功标准：用户无需反复翻找聊天记录或复制控件值；Agent 无需为每次交互重新制作网页，即可维护可读、可操作的共享工作资料。

02范围与版本边界

本文将功能分为首版必须具备（P0）与后续扩展（P1）。以下是本次规格采用的范围建议，作为后续评审与验收基线。

范围功能约定
P0 共享工作空间提供一块明确标识的当前看板，支持持久保存、网页展示、Agent 访问及断线后的状态恢复。首版围绕单用户与其授权 Agent 的协作。
P0 六类基础卡片文本、图片、文件、滑条、勾选框、输入框；用户与 Agent 均能创建、读取、修改和删除允许操作的卡片。
P0 看板整理拖动卡片、调整尺寸、修改标题、查找与定位卡片；已保存的布局对双方可见。
P0 Agent 协作卡片列表、完整读取、增删改、支持类型查询、看板快照、增量变化读取，以及允许范围内的资源添加和读取。
P0 可靠编辑局部修改、过时修改检测、重复请求保护、卡片锁定、删除后恢复、保存状态提示。
P1 扩展能力多看板管理、更多卡片类型、分组、完整历史与回滚、跨卡片批量操作、事件消费、导入导出和多人协作。

本规格之外

  • 内置聊天系统、模型调用与 Agent 执行调度；用户继续在已有 Agent 客户端中对话。
  • 通用网页设计器、任意 HTML 或脚本卡片、应用代码生成与运行。
  • 自动理解全部文件、自动提炼每轮聊天、自动判断工作结论是否正确。
  • 通过文件卡片直接编辑原文件，以及运行文件、命令或仿真任务。

03核心概念与角色

概念功能含义约束
看板围绕一项工作持续维护的共享空间，包含卡片及布局。有稳定标识和名称；所有操作须能确定目标看板，不能依赖猜测。
卡片可独立识别、展示和操作的最小元素。有稳定且唯一的标识；标题、位置和内容变化不改变身份。首版不支持原地转换卡片类型。
卡片定义决定卡片如何被使用的说明与约束，例如滑条范围、步长、单位。修改定义与修改当前值是不同的用户意图。
卡片状态当前共享内容，例如正文、图片引用、数值或勾选状态。显示值和 Agent 读取值在同一已保存版本下必须一致。
共享布局卡片的位置、尺寸和排列关系。整理布局不改变内容或控件值；页面滚动位置等个人浏览状态不作为共享内容。
资源供图片卡片、文件卡片引用的图片或文件。资源可被多张卡片使用；卡片与原始文件的生命周期分开。
版本与变更标识某次已保存状态，以及其后的新增、修改、删除或恢复。用于判断信息是否过时、读取近期变化和说明修改来源。

角色及默认权限

用户通过网页查看与整理看板，编辑卡片，添加资源，并管理锁定与访问范围。Agent通过 MCP 操作被授权的看板和资源。配套服务负责让两侧看到一致的已保存结果，并给出可理解的操作反馈。

普通卡片默认允许双方编辑，不设置「只有创建者可以修改」的隐含限制。卡片锁定与资源访问限制是明确的例外；Agent 无权自行扩大访问范围或解除用户锁定。

04典型协作流程

以下以原对话中的 PID 讨论为例，仅说明协作行为，不约定控制算法或计算功能。

  1. 建立共享背景

    用户打开看板并添加任务说明、参考文件。Agent 连接后确认当前看板，读取已有内容和支持的卡片类型。

  2. 把讨论对象放上黑板

    Agent 添加「Kp」滑条，初始值为 2.5；添加「允许的最大超调量」数值输入框，值为 20%，并保留参数含义和单位。

  3. 用户直接表达调整

    用户将 Kp 改为 3.0、补充限制条件，并移动参考资料卡片。页面明确显示保存结果。

  4. 在对话中继续工作

    用户回到 Agent 客户端继续讨论。Agent 重新读取相关卡片或近期变化，得到 Kp=3.0 和最大超调量=20%。

  5. 结果回到同一块黑板

    Agent 更新分析文字或添加结果图片。用户看到变化，可以继续编辑、锁定重要结论或恢复误删卡片。

  6. 下次从已保存状态继续

    关闭网页或结束对话后再次打开，卡片与布局仍保留；新会话通过读取看板恢复工作背景。

05看板与用户操作

编号功能预期行为
B-01打开与识别显示看板名称、稳定标识及连接状态。空看板提供添加卡片的入口，并说明 Agent 也可向此处推送内容。
B-02查看与定位查看卡片标题、类型和主要内容；可按标题查找，并通过卡片标识定位到具体卡片。长内容可展开阅读。
B-03添加与编辑用户可选择基础类型创建卡片，编辑标题、内容和控件定义；创建后立即获得可供 Agent 引用的稳定标识。
B-04整理布局支持拖动、调整尺寸及自动安排新卡片位置。默认排列避免遮挡已有卡片；空间不足时允许延展工作区域。
B-05操作控件控件操作与卡片拖动可明确区分。用户拖动滑条不会误移整张卡片，输入文字不会触发看板整理。
B-06查看变更来源卡片可查看最近修改时间及修改者；Agent 新增或更新内容时提供可识别的提示，不强制打断用户正在编辑的内容。
B-07保存与再次打开已保存的内容、控件定义、控件值、锁定状态和布局持续保留。刷新页面、重新打开看板或正常重启服务后可继续使用。

共享的是卡片布局关系。在不同窗口尺寸下，允许采用便于阅读的展示方式；仅缩小窗口不应被视为用户主动修改共享布局。

06卡片功能

所有卡片都应能表达：唯一标识、所属看板、类型、标题、内容摘要、位置与尺寸、当前状态、锁定状态和最近修改信息。摘要用于快速浏览，不能代替完整内容或精确控件值。

类型 / 编号承载内容双方可执行操作有效性规则
文本 C-01说明、约束、结论、临时笔记；支持纯文本及基础 Markdown 展示。读取和编辑完整正文、标题；保留换行及基本结构。正文与渲染展示含义一致；文本中的脚本或指令只作为内容，不自动执行。
图片 C-02图片资源、说明文字与来源信息。添加、查看、放大、替换图片，编辑说明；Agent 可获取允许访问的图片内容。资源不可用时保留卡片和说明，并显示具体原因；不假装已成功读取图片。
文件 C-03导入的文件副本或受控本地文件引用，以及用途说明。添加、读取元信息、访问允许读取的文件内容、替换引用；用户可预览或获取文件。明确显示导入／引用方式；不支持预览时仍保留文件获取入口；不自动执行文件。
滑条 C-04数值、最小值、最大值、步长、单位和用途说明。用户拖动调整数值；双方均可修改数值及范围等定义。最小值小于最大值、步长为正；值在范围内，并符合以最小值为起点的步长约束。
勾选框 C-05含义明确的标签与是／否状态。切换状态，编辑标签与说明。首版只含选中和未选中两种状态；未选中不等于信息缺失。
输入框 C-06单行文本或数值，可附单位、提示、必填与取值限制。输入与编辑当前值；修改允许的输入约束。明确区分空值、零和空字符串；不符合类型或限制的输入不成为已保存状态。

控件定义与当前值

修改标签不应重置数值，调整卡片大小不应改变内容。若修改定义会使现有值失效，应拒绝该次修改并说明原因；操作者可以同时提供有效的新定义和新值，一并完成修改。

创建控件时须提供有效初始值，或明确采用该类型公开说明的默认值。必填输入框不得以缺失值创建为有效状态；可选输入框允许保持空值。

图片可读取，不等于图片已被理解。框架须提供图片内容及附带说明；图片中文字的识别、图像语义理解和文件内容分析由具备相应能力的 Agent 完成。首版不保证自动 OCR 或自动生成准确摘要。

07Agent 操作能力

Agent 注册并获准连接后，应能够发现当前看板及可用能力，随后仅通过 MCP 指令完成常规看板操作。下表名称沿用原讨论，仅作为能力名称示意，不规定接口签名、参数结构或返回格式。

编号 / 能力功能结果
A-01 确认看板获得当前可访问看板的标识、名称及自身操作权限。首版可只返回一块看板；目标不存在或无权访问时明确拒绝。
A-02 查询类型
get_card_types		了解支持的卡片类型、用途、允许的内容与约束、默认值和操作限制。扩展类型在可用前应能被发现。
A-03 列出卡片
get_card_list		获取卡片标识、类型、标题、布局、摘要及状态新旧标记；大量结果应可分段读取，不能无提示遗漏。
A-04 读取卡片
read_card		获取完整正文、控件定义与当前值、资源信息、锁定状态及修改信息。大内容或资源需分步获取时，应明确可继续读取的范围与方式。
A-05 推送卡片
push_card		按已支持类型创建卡片，可指定标题、内容、控件定义及期望布局；未指定位置时由看板安排。返回稳定标识与实际创建结果。
A-06 编辑卡片
edit_card		按标识修改指定内容、定义或布局，其余内容保持原样。返回保存后的实际结果；遇到锁定或过时内容时说明原因。
A-07 删除与恢复
delete_card / restore_card		删除后移出正常视图，仍可从已删除列表找到并恢复。恢复沿用原标识；重复删除或恢复不产生额外副本。
A-08 看板快照
get_board_snapshot		获取同一时间点下的卡片集合与关键状态，并标识该状态的新旧程度。省略正文或资源内容时必须说明，支持按卡片补充读取。
A-09 增量变化
get_changes		读取已知状态之后的新增、修改、删除、恢复及保护状态变化，指出受影响卡片和修改者；不应遗漏删除或把多次变更误报为当前完整状态。
A-10 资源访问在允许范围内添加图片、导入文件或建立本地引用，并读取资源元信息和内容。资源不可访问时明确反馈，不以路径或摘要冒充内容。

Agent 应能区分「请求已提交」「已保存」「失败」与「结果未知」。调用失败须给出可采取的下一步，例如重新读取、修正数值或请求用户解除锁定。看板内容属于工作资料，其文字本身不构成新增权限或执行授权。

08共享状态与变更规则

编号规则可观察行为
S-01双方共享已保存结果任何一侧成功保存的修改，都成为另一侧后续读取的依据。网页正常连接时自动呈现外部更新，无需用户手动刷新。
S-02草稿与保存区分编辑中的文本或拖动中的暂态值可先作为本地草稿；只有明确保存成功的状态才成为双方共同依据。何时提交可以依控件交互确定，但状态必须可见。
S-03只改明确指定的内容Agent 仅修改标题时，不得把自己先前读到的旧数值写回。相同规则也适用于用户操作。
S-04过时修改不得静默覆盖基于旧版本的编辑或删除应被拒绝，并指出已有新状态。操作者重新读取后可重新提交；首版允许采用整张卡片范围的保守冲突判断。
S-05重复提交结果稳定对同一操作的重试不会重复创建卡片或重复应用修改；须能查明该操作是否已经成功，或明确说明结果仍未知。
S-06单次修改完整成立同一张卡片的一次修改全部有效才保存；例如修改滑条范围与数值时，不出现范围已改、数值被拒绝的半完成状态。
S-07断线后重新核对连接中断时提示已保存状态可能过时；恢复后重新读取当前状态。未提交草稿保留在当前页面中供用户处理，不自动覆盖期间的新修改。
S-08增量不可用时明确退回快照变化记录不足以完整覆盖请求区间时，提示重新读取看板快照；不能把部分变化冒充完整结果。

并发示例

Agent 读取 Kp=2.5 后，用户将其保存为 3.0。若 Agent 随后基于旧状态修改该卡片，应获得冲突提示；重新读取后，只更新需要修改的标题或说明，保留 Kp=3.0。用户正在编辑而收到 Agent 新版本时，也须能看到冲突并保留自己的未提交文字。

首版不要求逐字符协同编辑、自动合并复杂冲突或离线编辑后自动同步。本文不规定同步耗时数值，但要求操作状态明确且同步无需手动刷新。

09图片与本地文件

资源能力是图片与文件卡片的共同基础。用户可选择本地文件添加到看板；Agent 可从允许访问的来源添加资源。首版同时定义以下两种使用方式，以覆盖「添加文件」与「引用工作目录原文件」两类需求。

方式用户含义原文件发生变化时
导入副本向看板保存一份独立副本，适合资料、截图和阶段结果。原文件移动、删除或修改，不改变已导入副本。要更新需显式替换资源。
受控引用关联用户已允许访问的位置中的原文件，适合持续更新的工作文件。再次读取或刷新预览时核对资源状态；可访问时获取当前内容，失效时保留引用信息并提示。首版不承诺自动监控原文件每次修改。
  • R-01 可理解的来源：显示资源名称、类型、大小（可取得时）、说明与引用方式。引用文件读取结果应带可辨识的读取时间或内容版本信息，避免将旧预览误认为最新文件。
  • R-02 明确的访问范围：只有被用户选中导入或处于获准引用范围内的资源可被读取。无法建立受控引用时说明原因，并允许改为导入副本。
  • R-03 预览与读取：图片应可查看；其他文件能预览则预览，不能预览时允许获取原内容并提示限制。文件名、说明和路径不是文件全文。
  • R-04 可辨别的失败：区分资源不存在、访问被撤销、格式不支持、内容过大等状态；读取失败不删除卡片或清空先前说明。
  • R-05 生命周期分离：删除卡片不删除用户的原文件，也不破坏其他卡片对同一资源的引用。首版删除仍可恢复期间，导入副本须保持可恢复。
  • R-06 引用恢复：原文件移动后可由用户重新指定引用目标；恢复已删除卡片并不保证已失效的外部文件重新可用。

被引用原文件在看板之外发生的变化，不自动等同于一次卡片修改；Agent 需要最新文件时应重新读取资源，不能仅凭卡片变更记录推断文件未改变。

10保护与恢复

P-01 卡片锁定

用户可锁定重要卡片。锁定后双方仍可读取，但标题、内容、定义、控件值、布局和删除操作均不可修改。用户须先显式解锁再编辑；Agent 可以报告需要修改的原因，但不能自行解锁。首版不引入逐字段保护或审批流。

P-02 删除与恢复

删除操作使卡片进入可恢复的已删除列表，正常卡片列表不再展示；双方均可查询并恢复自己有权操作的卡片。恢复保留原标识、内容和资源关联，尽量恢复原位置；原位置被占用时安排到可见位置并说明布局调整。

首版不提供永久删除或自动清空已删除列表。恢复能力不等于完整版本回滚，编辑过的历史正文并不因此自动可恢复。

P-03 来源可追踪

每次已保存修改可识别修改者类别、时间及最新版本。近期变化可供 Agent 读取，用户可查看卡片最近修改信息。逐次差异、任意历史版本浏览和回滚属于后续能力。

P-04 操作范围受控

无权访问的看板或资源不能通过卡片标识绕过限制。卡片中的文字、Markdown、图片说明和文件内容按资料展示，不自动转化为脚本、系统命令或对其他资源的访问权限。

12功能验收场景

AT-01 双方建卡用户与 Agent 分别创建六类基础卡片。网页可查看；Agent 可列出和读取；所有卡片有独立稳定标识。B-03、C-01～06、A-03～05

13后续扩展

以下方向保留产品空间，但不作为首版交付承诺。新增卡片类型应继续复用「发现、创建、读取、编辑、删除」的统一操作方式。

方向用户价值需进一步明确的功能边界
多看板与分组按项目分开工作空间，折叠和整理相关卡片。看板创建、切换、归档、跨板移动和组内操作规则。
选择框、按钮表达有限选项，提交一次明确的操作意图。按钮点击是独立事件；连续两次点击须能区分，需定义待处理、已处理与失败反馈。
图表、表格、代码与画布承载更复杂的结果、结构化资料和空间关系。各类型的读取语义、编辑范围及可导出内容。
完整历史与回滚查看差异、理解演变、恢复误改。记录保留范围、回滚与当前编辑冲突、资源历史可用性。
批量修改与搜索高效整理多张卡片，查找正文和标签。批量失败是否全部撤销，以及跨卡片保护规则。
导入导出与模板迁移工作资料、复用常见协作场景。资源随附、外部引用失效、卡片身份与重复导入处理。
多人、多 Agent 与主动触发扩展协作角色，支持明确请求后启动工作。身份、权限、事件归属和执行反馈；主动启动 Agent 需要独立定义任务调度能力。
